# ADR-007: 证据绑定护栏用词法重合度，而非语义相似度

## Status

Accepted（2026-09-21）

## Background

护栏要回答的问题是：**"这句话是不是真的从引用的那段材料里来的？"**

最自然的做法是算语义相似度（嵌入向量余弦），甚至用 LLM 当裁判
（"请判断这个论断是否被材料支持"）。两者都比词法方法更准。

但它们都会给系统注入一个新的模型依赖，而且是**位于关键路径上的依赖**：
护栏是最后一道关卡，它挂了就意味着"要么全部拒答，要么全部放行"。

这与 ADR-002 的核心约束直接冲突：离线档必须无模型、无网络地跑通整条链路。
如果护栏依赖嵌入模型，离线档就没有护栏——那离线档验证的链路就不是真实链路了，
它验证的是一个"没有护栏的简化版"，这个验证的价值会大打折扣。

## Decision

用**词法重合度**作为判据，全部实现为纯函数，放在 `contracts/text.py` 与
`modules/guard/`：

| 判据 | 计算方式 |
|------|----------|
| 引用与原文的重合度 | 引用所在句子与目标块的分词集合交集 / 引用句分词数 |
| 问题与材料的覆盖度 | 问题内容词中被某条块包含的比例（用于答题前筛除） |
| 论断识别 | 够长（≥ `min_claim_chars`）、内容词够多、不以冒号结尾 |

四条硬规则（H1–H4）与一条软规则（S1）见 `docs/ARCHITECTURE.md` 第 4.5 节。

**阈值可配置且默认偏宽松**（`min_evidence_overlap = 0.05`、
`max_unbound_claims = 0`）。理由：词法判据对"改写过的正确引用"会误判，
而误杀一条合法回答的代价（用户拿不到答案）高于漏放一条轻微无据的论断
（用户还能自己看引用核对）。**宁可漏放，不可误杀。**

分词必须与检索共用 `contracts/text.py` 的同一套实现——两边不一致会导致
"检索召回了，护栏却说没有依据"这类极难排查的问题。

## Consequences

**正面**

- 护栏在离线档、CI、无模型环境下**完全可用**，两档的护栏行为一致。
- 纯函数，可被人工手算复核。`tests/unit/test_guard.py` 里的每个用例
  都能在纸上算出期望值。
- 无延迟、无额外成本（实测整条链路 7 ms 级）。

**负面**

- **对改写不友好。** 模型把"RRF 使用排名倒数"改写成"该算法基于名次而非分值"
  时，词法重合度可能低于阈值而被判为"装饰性引用"→ 整条回答被拒答。
  这是真实的假阴性来源。
- 无法识别"逻辑上不支持"：把两块材料拼接成一个材料里没有的结论，
  只要用词重合度高就会被放行。词法判据只看"是否来自"，不看"是否推出"。
- `min_question_coverage` 是词法判据，对同义改写的提问会过度拒答
  （在线档因此把默认值从 0.3 降到 0.15）。

**升级路径**：需要更强的判定时，实现 `Guard` 协议换一个语义/LLM 版本即可，
上层零改动。但必须同步放弃"离线档护栏等价"这一保证，
并在文档里明确写出——这是本 ADR 最需要被记住的取舍点。
