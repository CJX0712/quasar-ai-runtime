# ADR-012: 任何规划器下都必须有一次检索，且拒绝检测不自证

## Status

Accepted（2026-09-21）

## Background

ADR-011 声明"至少会检索一次"是**结构性保证**，理由是`7B 级模型会忘记调工具`。
但实现只在 `planner == "rules"` 时预检索；`llm` 档完全把取证交给模型。

实测把在线档 `configs/local.toml.example` 的 `planner` 设为 `llm` 后，
跑真实链路（Ollama + qwen2.5:7b-instruct-q4_K_M + bge-m3，9 个块的语料）：

```
=== 检索 ===   184ms · 词法命中 9 / 稠密命中 9 / 返回 5 条     ← 检索本身完全正常
=== 问答 ===   38742ms · 拒答=True · 工具调用 0 次 [] · 步数 1
拒答原因：知识库里没有任何可用材料，无法回答该问题。
--- 证据（模型实际看到的材料）---                            ← 空
```

三个层面的问题叠在一起：

1. **功能性**：`llm` 档下问答的真实成功率是 0%。检索器 184ms 就能拿到 5 条材料，
   却因为没人去拿，整条链路必然拒答。而 ADR-011 正是为了避免这个才写的。
2. **文档漂移**：ADR-011 描述的保证与实现不一致，读 ADR 的人会以为这条路已经兜住了。
3. **诊断性**（单独记为 ADR-013）：拒答原因把"模型没调工具"报成"知识库里没有可用材料"，
   把一个规划器配置问题指向了一次毫无意义的重建索引。

## Decision

把"至少检索一次"从**声明**变成**任何规划器下都成立的不变量**。
`planner=llm` 的语义收窄为：

> 模型可以在首次作答前自行追加任意工具调用；
> 但**若它没有取得任何材料就给出最终答案，系统必须替它检索一次**，再让它重答。

实现（`modules/agent/loop.py`）：

```
无 tool_calls 且 evidence 为空且 planner=llm 且 retriever 可用且尚未兜底过
    → 用 pre_retrieve_k 直接调 retriever（不经过工具层）
    → 命中：把模型那次作答连同材料一起回灌，要求它带 [n] 重答一次
    → 未命中：确认是真的没材料，继续走正常 screen → 拒答
```

三个约束：

- **只兜底一次**。用局部变量 `seeded` 而不是实例属性——`AgentLoop` 是长生命周期
  单例，实例状态会跨请求污染。无材料时反复兜底只会烧模型调用。
- **不经过工具层**。兜底走 `self.retriever`，所以 `tool_calls` 计数保持为 0——
  这样"模型自己调了几次工具"这个指标不会被系统的兜底污染。
- **流式路径同样适用**。`stream()` 没有工具循环，原本在 `llm` 档下必然拒答；
  现在它在开流前做同样的一次补检索，并把材料插到用户提问之前。

配套把 `configs/local.toml.example` 的默认值改回 `rules`（与 `default.toml` 一致），
并在注释里写下这次实测结论。`llm` 保留为显式选项，用于验证多步工具组合。

## Consequences

**正面**

- `llm` 档的问答成功率不再取决于模型是否记得调工具；ADR-011 承诺的保证真正成立。
- 兜底是**懒执行**的：模型自觉调了工具就不触发，省掉一次检索。比"无条件预检索"
  更省，且行为可观测（trace 里有 `seeded` 字段）。
- 三个失败层面各归其位：功能靠兜底、文档靠勘误、诊断靠 ADR-013。

**负面**

- `llm` 档在模型漏调工具时会多花**一次模型调用**（拿它那次无用作答 + 一次带材料重答）。
  实测这次重答 ~20s。比"直接拒答"贵，但比"给用户一个拒答"值。
- 多了一个"系统代替模型决策"的动作，纯 ReAct 的语义纯度下降。
  这是刻意的：`llm` 档的兜底不改变主干流程，只封住下限。
- 兜底逻辑在 `run()` 与 `stream()` 各有一份（两处结构不同，无法共用一段代码）。
  已用同一句注释交叉标注，改一处时必须看另一处。
