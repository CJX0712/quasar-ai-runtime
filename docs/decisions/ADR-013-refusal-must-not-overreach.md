# ADR-013: 拒答原因只能陈述可观测事实，且必须自带排障方向

## Status

Accepted（2026-09-21）

## Background

护栏的 `screen()` 在材料为空时原本返回：

```
知识库里没有任何可用材料，无法回答该问题。
```

这句话断言的是**知识库的状态**，而护栏能够观测到的只是**本次调用拿到的材料**。
两者不是一回事，实测中它们确实不同：

- 语料里明明有 5 篇文档 / 9 个块，检索器 184ms 就能返回 5 条命中；
- 拒答却报"知识库里没有任何可用材料"。

按这句话去排障的人会去重跑 `quasar ingest`、去检查 `assets/corpus`、
去看向量库文件有没有写坏——全部是死路。真实原因是 `planner=llm` 下
模型没有调用检索工具，材料根本没被取过。

这类缺陷比"功能没实现"更难发现，因为它**看起来像一个已知的正常行为**：
拒答本来就是这个系统的合法输出（ADR-008），原因字段也非空、读起来通顺。
它唯一的破绽是原因与事实不符，而这只有对照同一份语料跑一次检索才会暴露。

同一路径上还有第二个问题：`planner=llm` 且无材料时，最可能的故障原因是配置，
但拒答原因里没有任何指向配置的线索，排障者要从零开始猜。

## Decision

两条规则，适用于所有 `GuardVerdict.reason`：

**规则一：断言范围不得超过观测范围。**

护栏只看得见传进来的 `evidence`，所以只能说"本轮没有取得任何可引用的材料"。
凡是"知识库是空的""语料没有被正确采集"这类关于系统其他部分的断言，
一律不允许出现在护栏文案里——护栏没有那个视角。

```
- 知识库里没有任何可用材料，无法回答该问题。
+ 本轮没有取得任何可引用的材料，无法回答该问题。
```

**规则二：当故障的成因分布不唯一时，原因里必须带排障方向。**

`AgentLoop` 在"无材料 + `planner=llm`"这条路径拒答时，在原因后追加：

```
（agent.planner=llm：模型本轮未通过工具取得材料，兜底预检索也未命中。
 若希望每问都确定性预检索，把 agent.planner 改为 rules）
```

这句只在**该条件成立时**才追加。护栏本身保持通用，不做配置相关的判断——
把它写进 `modules/agent/` 是因为"规划器配置"是智能体层的概念，不是护栏层的。

## Consequences

**正面**

- 拒答原因从"读起来通顺"变成"能被证伪"。前者是文档，后者是诊断。
- `planner=llm` 的配置误用会在第一次拒答时自曝，不需要读代码或读 ADR。
- 护栏文案与 `AgentLoop` 的补充文案职责清晰：护栏说"这一轮发生了什么"，
  智能体说"这在系统里意味着什么"。

**负面**

- 拒答原因变长，且含有一个只在特定条件下出现的括号补充。调用方若要做
  原因字符串匹配（例如按"覆盖度"关键字分流），必须知道存在这段后缀。
  已把两个新增文案集中在 `modules/agent/prompts.py`，避免散落在分支里。
- 原因里出现配置项名会把内部结构暴露给终端用户。这里接受该代价：
  本系统的拒答原因首先是给运维者读的，不是给产品文案用的；
  面向终端用户的措辞由 `guard.refuse_message` 单独负责（它保持简洁不变）。
