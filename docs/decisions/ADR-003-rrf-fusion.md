# ADR-003: 用 RRF 融合多路召回，而非加权求和

## Status

Accepted（2026-09-21）

## Background

混合检索要把词法（BM25）与稠密（余弦）两路结果合并成一个排序。
最直觉的做法是加权求和：`score = w₁ · bm25 + w₂ · cosine`。

但这两路的分数**量纲完全不同**：

- BM25 的分数无上界，取决于词频、文档长度、语料规模。同一份语料加一篇文档，
  所有 BM25 分数都会变。BM25Plus 因为带 `delta` 分量，分数还会整体抬高。
- 余弦相似度在 `[-1, 1]`，且实际分布高度集中在 `[0.3, 0.9]`（取决于嵌入模型）。

把它们直接相加，权重 `w₁/w₂` 就变成"分数尺度比"的函数而不是"相关性重要度"的函数。
换一个嵌入模型、语料长一倍、或者换成 BM25Plus，最优权重就全变了——
这意味着**每次动语料或换模型都要重新调参**，而调参需要标注数据。

## Decision

使用 Reciprocal Rank Fusion（RRF）：

```
score(d) = Σ_i  weight_i / (k + rank_i(d))     k = 60
```

只用**排名**，不用原始分。常数 `k = 60` 取文献常用值，作用是压平头部差距
（排名 1 与 2 的差距不因 `k` 小而变得极端）。

两路都不包含 `d` 时该项不贡献；只在一路出现的文档也能被召回，
但两路都排名靠前的文档会显著胜出——这正是我们想要的"互相印证"信号。

`weight` 仍保留（`lexical_weight` / `dense_weight`），但它的语义从
"分数缩放"变成了"该通路的票权"，对量纲不敏感。

## Consequences

**正面**

- 换嵌入模型、改语料规模、切换 BM25 变体，都不需要重新调权重。
- 可解释：给用户展示"这条命中在词法排第 2、稠密排第 5"比展示一个混合分数更有用。
- 实现只有约 30 行纯函数，可单独单测（`tests/unit/test_rrf.py`）。

**负面**

- 丢掉分数幅度的信息：BM25 给出 12.7 分（远超第二名的 3.1 分）与"只赢一点点"
  在 RRF 里被一视同仁。对"某个词精确命中"这类强信号，RRF 表达力不如加权求和。
- `k = 60` 是个经验常数，没有针对本项目语料做过标定。
- 权重不再是连续可微的调参旋钮，难以做细粒度优化。

缓解措施：把 RRF 的输出当作"候选顺序"，后面接一层重排（词法或 LLM），
由重排器在头部做精细排序。RRF 负责"不丢东西"，重排负责"排对顺序"。
