# ADR-016: 多轮追问的相关性继承

## Status

Accepted（2026-09-21）

## Background

ADR-015 把相关性判据修正为查询侧分词之后，在线档暴露出下一个问题：
**多轮追问被误杀**。实测序列：

```
第 1 轮：混合检索里的融合算法是什么，常数 k 默认取多少？
        → 正常回答："RRF（倒数排名融合）……常数 k 的默认取值是 60。[1]"
第 2 轮：那这个常数取大一点会怎样？
        → 拒答。原因：覆盖度 0.100 < 门槛 0.300
```

第 2 轮的答案（"k 越大结果越均衡"）明明就在语料里，第 1 轮也确实答对了。
问题出在追问的**字面**：它的主语"这个常数"在第 1 轮里，按字面算覆盖度必然失败。
检索同样受害——拿这句追问去查，召回的也是无关材料。

这不是 ADR-015 的设计错误，而是它的**已知负面项在多轮场景下的显形**：
"问法与语料用词差异大的合法问题更容易被误拒"，追问是其中最极端的一类——
它的字面根本不构成一个独立的问题。

## Decision

相关性判据获得一个**继承规则**：追问可以从它所追问的上一问继承相关性。

实现分三步（`modules/agent/loop.py`）：

1. **还原**（`_resolve_question`）：从历史轮次里取最近最多 3 条**用户**输入，
   拼接到追问前面作为检索查询（`effective`），其中与本问共享内容词的
   条目单独返回为可继承列表（`antecedents`）。只拼用户输入、不拼助手回答——
   回答的内容来自语料，拼进去会让任何追问都"命中"语料，筛除彻底失效。
   取 3 条而不是 1 条，是因为上一轮可能恰好是换话题或被拒答的轮次
   （实测发生过：RRF 问答之后夹一轮语料外提问，再追问常数 k 时
   "只取最近一条"就继承不到了）。

2. **继承裁决**（`AgentLoop._screen`）：先按**本问原文**裁决；不通过时按
   `antecedents` 逐个裁决，任一通过即放行。语义：历史问在上轮已经通过
   同一道筛除，追问延续同一话题时不该被重复拦下。全部不通过时，
   返回本问版的原因。**拼接版（effective）只用于检索、绝不用于筛除**——
   实测教训：换话题的新问题混上历史问的命中词后，覆盖度会从 0.194
   被抬到门槛之上（约 0.31），筛除形同虚设。

3. **窄化**：只有当候选上一问与追问**共享至少一个内容词**（查询侧分词的
   交集）时才可继承。否则视为换了话题，完全不搭界的新问题不得蹭
   历史问的覆盖度。

为什么"检索用拼接、筛除用继承"：拼接版的覆盖度会被**稀释**——实测
"上一问 + 追问"的拼接覆盖度约 0.32，贴着 0.3 的门槛，换个问法就会翻车。
而检索不怕词多：多带一些上一问的词只会提高召回。两个用途，两套策略。

## Consequences

**正面**

- 合法追问不再被误杀；实测在线档第 2 轮能正确答出"k 越大结果越均衡"。
- 追问的检索质量同步提升（查询带上主语后召回不再跑偏）。
- 继承的代价结构清晰：单轮路径零改动、零开销；有历史时多两次纯词法计算。

**负面**

- **换话题的追问会多花一次模型调用才被拒答**：它通过了筛除（因为没有继承，
  按 effective 裁决……注意换话题时 antecedent 为空，走的是字面裁决），
  真正的代价在护栏的 `check` 环节——模型面对不相关材料要么硬凑引用、
  要么声明材料不足，后者会触发一次重写。换来的是合法追问不被误杀，
  这笔账是划算的，但调用成本上界（max_retries=1）要心里有数。
- 共享内容词是个粗糙的话题判定："那这个呢？"这种极简追问与上一问可能
  只共享一个"这个"之外的内容词，判定结果取决于措辞。它不会放走不相关
  材料（材料还是要过 `check` 的证据绑定），最坏情况是回到"误拒"。
- 历史轮次来自 memory 或显式 history，`_resolve_question` 只看最近一条
  用户输入。跨两轮以上的指代（"跟第 3 个问题相比呢？"）不支持。
