# ADR-002: 双模态运行（offline / online）

## Status

Accepted（2026-09-21）

## Background

需求里有一条硬要求：**确保在干净环境中可一键复现**。同时系统又必须真能调用大模型。
这两件事天然冲突——干净环境里没有模型权重、没有推理服务，
而下载 6 GB 模型显然不属于"一键"。

如果只做在线档，CI 要么不跑（等于没有持续验证），要么每次下载模型（慢且脆弱）。
如果只做离线档，交付的就是一个玩具。

## Decision

把"链路"与"装配"分离，定义两种运行档：

| | offline | online |
|---|---|---|
| LLM | `scripted`（确定性抽取式合成） | `ollama` / `openai_compat` |
| 嵌入 | `hash`（哈希投影） | `ollama` bge-m3 |
| 重排 | `lexical` / `none` | `lexical` / `llm` |
| 外部依赖 | 零 | Ollama 服务 |

两者**共用同一份 L2/L3/L4 代码**，只有 L1 的实现选择不同，
而选择发生在唯一装配点 `container.build_services()`。

配套两条约束：

1. `Settings.validate_config()` 拒绝"`mode = offline` 但配了在线实现"的组合。
   离线档的保证是"无模型无网络也能跑通"，允许混入在线实现会让这个保证静默失效。
2. `tests/e2e/test_online_ollama.py` 里的在线用例在模型不可用时**显式 skip**，
   不静默通过。skip 数量是可观测的（当前 6 个）。

## Consequences

**正面**

- CI 在 GitHub 干净 runner 上完整跑通链路，零模型依赖，20 分钟超时绰绰有余（实测 8 秒）。
- 同一套契约测试能同时覆盖两档实现，`hash` 与 `bge-m3` 走完全相同的断言。
- 用户可以先用离线档确认装配无误，再切在线档，排查面收窄一半。

**负面**

- `scripted` LLM 必须自己实现"看起来合理的回答"，这段代码是纯粹的工程成本，
  且它永远是链路里最"假"的一环（虽然它是确定性且可断言的）。
- 两档之间的行为差异需要显式记录，否则会出现"离线通过、在线拒答"的困惑。
  实际开发中确实发生过：离线档 `min_question_coverage = 0.3` 对在线语义检索过严，
  导致所有问题被拒答——现已在在线档配置模板里显式降到 0.15 并写明原因。
- 需要维护两套配置模板。
