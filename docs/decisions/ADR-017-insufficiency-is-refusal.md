# ADR-017: 模型自陈"材料不足"必须如实上报为拒答

## Status

Accepted（2026-09-21）

## Background

在线档真跑时观察到这样一条回答：

```
问题：这家公司上一财年的净利润增长率是多少？（语料里没有这个知识）
回答：材料不足以回答此问题。[1] [2] [3] [4] [5] 中未提及该公司上一财年的净利润增长率。
结果：refused=false · 引用 5 处
```

模型的行为完全符合设计——SYSTEM_PROMPT 第 3 条要求它"材料不足时直接说明"，
第 2 条要求它"每一句事实陈述后标注 [n]"。它两条都照做了：说明材料不足，
并给每个句子补上编号引用。

但系统把它们拼成了一个语义上错误的结果：`refused=false` 意味着"这是一条
有据可查的回答"，调用方拿到的却是"我没有答案"。**引用格式洗白了自陈内容**：
护栏的引用校验只看 [n] 是否存在、是否越界、重合度是否达标——五个引用
全部命中材料（"未提及"这个词本身就能和材料词法重合），于是放行。

这是 ADR 索引里"静默失效"模式的又一个变体：程序正确、护栏放行、
只有语义是错的。它比崩溃难发现得多，因为每个环节单看都是对的。

## Decision

护栏的 `check()` 新增一条**先于引用校验**的规则：

> 若答案文本自陈材料不足，判定为拒答，且为终局判定（`terminal=true`，
> 不进入重写重试）。

- 识别用词法模式（"材料不足 / 不足以回答 / 无法回答 / 未提及 / 信息不足……"），
  集中在 `evidence.py` 的 `_INSUFFICIENT`，不依赖模型调用，离线档可用。
- **终局**的原因：重写注定得到同样的自陈——材料确实不足；
  而且重写指令（"每个段落都要带 [n]"）只会逼着模型把"材料不足"
  包装得更像答案。
- 识别放在引用校验**之前**：引用校验拦不住"格式合规的非答案"，
  这正是本 ADR 要修的洞。

`terminal` 是 `GuardVerdict` 的新字段（契约层），智能体循环在
`verdict.ok or verdict.terminal or retries >= max_retries` 处短路。

## Consequences

**正面**

- `refused` 恢复它应有的语义：false 当且仅当"给出了一条带引用、可核对的回答"。
  下游（HTTP 调用方、CLI、评测）不再需要自己解析答案文本判断是不是非答案。
- 实测直接收益：语料外问题的响应从 83s（模型调用 + 5 引用洗白）
  回到相关性筛除的毫秒级拒答路径。

**负面**

- **词法模式必然不完备**。模型换一种说法（"这个问题超出了资料范围"）就漏，
  退回到 `refused=false` 的旧行为。模式列表可继续补充，但治本是让模型
  用结构化字段声明拒答（例如工具调用 `refuse` 或特殊 token）——
  那需要模型侧配合，7B 级模型不可依赖，故选词法兜底。
- **误伤风险**：合法回答里若包含自陈措辞（"资料中没有提到 X，但 [1] 说明了 Y"），
  会被整条拒答。按 ADR-008 的代价不对称原则（"漏放一条可疑回答，用户还能
  核对引用；误杀一条合法回答，用户什么都拿不到"）这里选了相反的方向：
  自陈措辞意味着模型自己对材料没把握，此时宁可拒答。阈值没有做成配置——
  先观察误伤率，有数据再决定。
