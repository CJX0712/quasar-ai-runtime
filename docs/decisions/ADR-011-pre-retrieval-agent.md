# ADR-011: 智能体预检索 + 可选 planner，而不是纯 ReAct 循环

## Status

Accepted（2026-09-21）

## Background

智能体部分（`modules/agent/loop.py`）有两种典型实现路线：

**路线 A：纯 ReAct 循环。** 循环体是"模型输出 → 若有 tool_call 则执行并回灌 →
否则结束"。检索是一个由模型决定是否调用的工具。

**路线 B：固定管线。** 先检索，再把材料塞进提示词，然后生成。

A 的问题在本地小模型上很突出：qwen2.5:7b 这类模型在"回答一个明显需要检索的问题"
时有相当概率直接开始编答案，不调用工具。它不会报错，只是悄悄绕过了检索，
于是护栏在最后一步拒答——用户看到的是"知识库中没有依据"，
而真实原因是"模型忘了用工具"。

B 的问题是没有智能体性：模型无法追问、无法计算、无法按需二次检索，
只能一次性吃下所有材料。

## Decision

采用**预检索 + 模型决定是否继续调用工具**的混合结构：

```
prepare(question):        记忆召回 + 一次预检索 → evidence（必定发生）
screen(question, evidence): 材料与问题无关 → 直接拒答（必定发生）
loop (≤ max_steps):
    LLM.chat(messages, tools)
      ├─ 有 tool_calls  → 执行 → 回灌 → 下一轮
      └─ 无 tool_calls  → 得到答案
check(answer, evidence):   证据绑定校验 → 通过 / 重写 / 拒答
```

关键点：**证据的获取不依赖模型的自觉。** 模型只需要在"一次检索不够"时
追加工具调用（比如需要 `calculator` 算百分比、需要 `now` 拿当前时间），
而不是承担"记得要检索"这个负担。

`planner` 配置项区分两种行为：

| 值 | 预检索 | 工具 schema | 用于 |
|----|--------|-------------|------|
| `rules` | 在 `prepare` 阶段必定执行 | 照常传给模型 | 事实型问答默认档 |
| `llm` | 不执行，材料全靠模型自己调工具取得 | 照常传给模型 | 验证多步工具组合 |

> **勘误（2026-09-21 实测）**：本 ADR 初版把上表写成"`rules` 不把工具暴露给模型"，
> 与实现不符——`llm.chat(messages, tools=...)` 是两条路径共用的，`rules` 下模型
> 同样拿得到工具 schema。实现是有意这样做的：预检索保证底线，工具提供上限。
>
> 更要紧的是初版**把"预检索必定发生"写成了全局保证**，而实现只在 `rules` 下预检索。
> 于是 `planner=llm` 时"至少检索一次"这个保证其实并不存在——见 ADR-012。

## Consequences

**正面**

- **至少会检索一次**这个保证在 `rules` 下是结构性的，不依赖模型行为。护栏的
  `screen`/`check` 因此总是有材料可查。（`llm` 下的保证由 ADR-012 的兜底补齐。）
- 离线档可用 `rules` 走完全确定性的路径，`scripted` LLM 只需要实现
  "根据证据合成答案"，不必模拟工具调用决策。
- 在线档的增量能力（计算、时间、二次检索）通过 `llm` 打开，
  且不改变主干流程——两档共享同一条 `prepare → screen → loop → check` 骨架。
- 预算约束集中在 `max_steps` + `max_tool_calls` 两个数字上，便于推理上界。

**负面**

- **失去一次"完全不需要检索"的机会。** 对一个常识问题（"1+1 等于几"），
  预检索仍然会跑一次，浪费一次嵌入 + 检索（离线档实测 < 5 ms，在线档约 0.5–2 s）。
  对这个场景，纯 ReAct 更省。
- 预检索的 `pre_retrieve_k` 与后续工具调用的 `top_k` 是两个独立参数，
  调参面比纯 ReAct 略大。
- `rules` 模式下材料已经备好，模型调工具的动机很弱，"智能体"在实践上退化为
  "固定 RAG 管线 + 可选工具"。这是可接受的——事实型问答的可验证性优先于智能体性。

**为什么不用"让模型先判断是否需要检索"这一步**：那会引入一个额外的 LLM 调用，
而且判断错误时的后果（漏检索 → 拒答）比"多检索一次"（数毫秒到数秒）严重得多。
用一次可接受的固定成本换掉一个不可靠的判断，是划算的。
