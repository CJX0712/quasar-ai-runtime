# Quasar 系统概述

Quasar 是一套模块化、单一职责、端到端可实际运行的 AI 运行时，作者是晨星。

## 分层结构

Quasar 采用五层结构，依赖只向下传递，最底层是 L0 契约层：

- L4 接口层：命令行、HTTP 接口、以及一个零外部依赖的单文件 Web 控制台。
- L3 编排层：依赖注入容器、链路装配、结构化追踪、自诊断。
- L2 能力层：采集、检索、记忆、智能体、护栏、工具、评测，共七个能力模块。
- L1 适配层：契约的具体实现，可以随时替换。
- L0 契约层：全部以 Protocol 与 pydantic 数据对象表达，是整条链路唯一允许被依赖的终点。

依赖倒置是这套结构的核心约束。任何 L2 能力模块都不允许直接引入 L1 的实现类，
只能声明自己需要哪个契约，由 L3 的容器在装配时把具体实现注入进去。

## 核心模块职责

采集模块负责把文档加载、切分并写入向量库与词法索引两套索引。
检索模块负责混合召回与融合排序，本身不生成任何文字。
记忆模块负责短期会话窗口与长期相关召回，两者语义不同，分开实现。
智能体模块负责编排一次问答的完整控制流，不实现检索、工具与护栏。
护栏模块负责证据绑定校验，是纯函数，不依赖任何外部服务。
工具模块提供检索、计算、时间、JSON 查询四类内置工具。
评测模块负责在独立索引上运行黄金集并产出可复核的指标报告。

## 两种运行模式

离线模式不依赖任何模型与网络，使用确定性脚本模型、哈希嵌入、词法重排和内存向量库。
它的用途是让整套链路在干净环境里可以被完整验证。
在线模式使用本机的 Ollama 服务，生成模型默认是 qwen2.5 7B 的量化版本，
嵌入模型默认是 bge-m3，维度为 1024 维。重排默认走大模型重排。

## 默认实现选型

默认的向量库实现是 numpy 精确检索，而不是近似近邻索引。
在知识块数量低于一万时，精确余弦检索比近似索引更快也更准，而且不引入额外依赖。
需要更大规模时把配置里的向量库实现改成 qdrant 即可，上层代码无需改动。
